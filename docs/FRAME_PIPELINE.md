# LCD 等待与重复帧优化（2026-11-11）

本轮从主仓库 `e3f60aa`、核心 `8689b5b` 开始，保留相同的 240×320、MAX SIZE、JIT 关闭及双核/SIMD/PPA 开启配置。设备使用 `/dev/ttyUSB1`，只写应用分区。

## 保留的修改

LCD 继续使用两块 GDMA 帧缓冲。提交后将缓冲交给驱动，等到下一次访问可写 LCD 缓冲时，才等待释放事件并通过 DMA2D 同步脏区。VM 因此可以在 LCD 切换期间继续处理 Java 计算和原生图像。取得可写缓冲、直接 DMA blit、截图和显示检查都会先完成这个等待；前一个帧缓冲尚未释放时不会重用它。没有增加额外帧缓冲。

原先的整帧探针在发现变化后会把影子帧标记为无效。下一次提交相同画面时，适配器只能补建影子并再次提交 LCD，导致重复刷新。现在探针发现变化时同时更新影子；随后必须经过完整字节比较，才能确认可以跳过刷新。部分刷新仍仅提交声明范围内的像素。

开发时可用 `-DKORVO_DISPLAY_PIPELINE=OFF` 恢复同步等待，默认开启。这个编译选项不增加用户界面设置；原有 NVS 设置和 Pixel Perfect 默认关闭的行为保留。

## 测量方法

新增 `FramePipelineBench`：四档固定 Java 计算量，每档恰好绘制 48 个不同画面，共 192 个画面。每帧请求重绘并让出执行；计算结果、实际 paint 数量、最终原生画面及 LCD 区域 CRC 一并核对。两版各运行两轮，截图不参与计时。该夹具说明计算和显示等待的关系，不能将其单项提升换算为所有游戏的帧率提升。

```sh
python3 tools/build_parallel_fixture.py --kind pipeline
python3 tools/benchmark_pipeline.py build/pipeline-results.json
```

脚本按设备当前列表自动发现夹具；缺少时上传，通过 CRC 校验。测试使用全新临时 RMS，结束后恢复原有显示/JIT 设置。保留的 JAR 源码可以重建，商业游戏 JAR 不提交。

详细数据见 [优化前](updates/2026-11-11-performance/pipeline-sync32.json)、[最终固件](updates/2026-11-11-performance/pipeline-after.json) 和 [汇总](updates/2026-11-11-performance/summary.json)。同步对照固件采用相同 `fca2cd8` 核心，带有下文的 32 KiB 内存池试验；它在纯计算和 3D 固定任务中没有测得加速。最终固件撤回内存池和 IRAM 试验。

| 每帧计算循环次数 | 同步版本均值 | 最终版本均值 | 耗时减少 |
| --- | ---: | ---: | ---: |
| 0 | 1,496 ms | 1,330 ms | 11.10% |
| 2,000 | 4,554.5 ms | 2,448 ms | 46.25% |
| 6,000 | 6,833 ms | 4,895 ms | 28.36% |
| 12,000 | 10,273 ms | 9,082 ms | 11.59% |

合计均值从 **23,156.5 ms** 降到 **17,755 ms**，减少 **23.33%**。两版每轮均实际 paint 192 个画面；LCD 更新由 **337 次降到 192 次**。每轮原生 CRC `af47ddc1`、LCD CRC `6c1c0bf2` 和四段 Java 校验值完全相同，退出 `rc=0`、PSRAM `delta=0`、缩放差异为 0。最终版本单轮画面提交累计约 4.0 秒，同步版本约 9.4 秒。

纯 M3G 固定任务保持原有水平：四项耗时变化在约 0.5% 内，四个 Java 校验和以及原生 CRC `c4e65f9a`、LCD CRC `658aacbb` 一致。本轮改善主要来自显示等待和重复提交，未据此宣称三角形光栅器加速。

## 未保留的试验

- 内部快速内存池：旧的 256 KiB 门槛使测量时只有 255,567 字节空闲的设备不启用它。试验在保留 192 KiB 余量后启用 32 KiB 私有池，峰值约 30 KiB，但纯计算和固定 3D 任务均没有可重复收益。最终恢复原来的内存策略。
- M3G IRAM：将 `sw_span` 和 `sw_tri_band` 共 14,454 字节放入 IRAM，Gouraud 任务改善约 3.5%，最近邻纹理任务却慢约 2.8%，其余项目接近。最终撤回这项改动，保留内部 RAM 余量。数据见 [试验记录](updates/2026-11-11-performance/m3g-iram.json)。
