# 上游更新、240×320 游戏与 FPS

本页记录 `fed8d0c` 及此前版本。后续 `fe974fc` 的最新基准、3D 游戏实测和固件状态见 [LATEST_3D.md](LATEST_3D.md)。

2026-10-22，ESP32-S31-Korvo-1，CPU 320 MHz，PSRAM 250 MHz，无 SD 卡。仅烧录应用，保留游戏分区和正常 RMS 存档。游戏和固定工作量测试均使用 **240×320**、音量 40；早期探索使用过其他分辨率，不纳入本页最终数据。

## 上游与集成

子模块由 `179722a` 更新至 `fed8d0c3d2e42560c9bc33dba3288989412e043f`（`feat(jit): add configurable RV32 baseline compiler`）。保留上游源码原样，所有构建参数、内存回调和 UI 改动位于主仓库。升级期间还验证了 IO/Reader、RMS 时间戳、Micro3D/M3G 更新；最后一次拉取由用户明确要求的 RV32 JIT 更新触发。

解释器整个编译单元放入 IRAM。关闭融合指令的同核心实验（`01f32c5`）将固定计算平均耗时从 10.735 s 降至 9.597 s，因此 `KORVO_SUPERINSTR` 默认关闭。扩大内部 RAM 对栈尺寸块的预算后，实测栈分配确实使用内部 RAM，但固定计算未表现出额外收益，不单独宣称加速。通用元数据预算 96 KiB，栈尺寸块上限 160 KiB，分配前为驱动保留 96 KiB；不足则回退 PSRAM。

## FPS 开关

右上角 `FPS OFF` / `FPS ON` 在菜单及正常游戏中均可切换，默认关闭。开启后在游戏画面左上角每 500 ms 统计一次实际更新帧率，静止画面降为 0。重复提交的相同画面不计入，不等于 LCD 扫描刷新率或 VM 调度帧率。关闭立即恢复覆盖区域。

叠加只写 LCD，游戏原始缓冲保持原样；`shot game` 不包含叠加，`shot full` 包含全部按键和叠加。CRC/缩放检查排除叠加覆盖像素，其余区域仍逐像素校验。方向键三角形和中央正方形保留。

在 `7b12084` 的固定重绘验证中，关闭时两轮平均 8.0355 s，开启时 8.0670 s，约增加 0.4%；两组原始画面 CRC `c28d5ef8`、归一化 LCD 游戏区域 CRC `df7449c1` 相同，`scale_mismatch=0`，退出后内存全部恢复。截图和串口开关也通过。读取 LCD 截图会暂停 VM，因此截图过程的 FPS 或音频欠载不纳入性能测量。

自动 `bench` 模式隔离触摸按键（保留 MENU 中断）；串口输入和指定帧按键脚本仍有效。FPS 可在开始前或通过串口切换，用于专门的开关验证。正常 `run` 模式支持屏幕上的 FPS 按钮。

## RV32 JIT 实机验证

**已经在本板执行生成的 RV32 机器码，但当前版本实测更慢，因此默认关闭，保留 `jit on` 试验开关。** JIT 开关仅在菜单修改，对下次启动生效；`KORVO_JIT=ON` 表示编译支持，不代表运行时默认启用。

同一固件、相同 JAR、固定 240×320、关闭 FPS、无输入、全新测试 RMS。固定计算和重绘各两轮，其余各一轮：

| 测试 | JIT 关闭 | JIT 开启 |
| --- | ---: | ---: |
| 固定计算，含加载/显示/销毁 | 9.7966 s | 14.7888 s |
| 240 次完整重绘 | 8.0510 s | 8.0762 s |
| 极品飞车14，300 VM 帧启动场景 | 7.7235 s | 7.8976 s |
| 极品飞车16，300 VM 帧启动场景 | 14.1432 s | 16.4610 s |

这些时间包含运行器、资源和销毁，不能将 VM 帧数换算成实际不同画面的数量。固定计算开启 JIT 耗时增加约 51%；重绘基本不变。跨版本比较，当前关闭 JIT 的固定计算仍慢于初始优化核心 `179722a` 的 8.931 s，不能把拉取新核心视为整体加速。

每轮 CPU 的 `JIT_STATS` 为 `compiled=2241 executed=3920966 bytecodes=6460115`，实际运行约 392 万次原生块，原生块平均约 1.65 个 Java 指令。代码缓存峰值 976 B（含主工程分配头），全部提交成功、无内存分配拒绝。极品飞车16 则编译 20,340 个块、执行 697,340 次，缓存发生大量替换。结合上游的短直线块设计、字段/分支/调用保留解释执行，以及每块入口的检查和状态保存，推断当前成本超过了所节省的解释器分发；这不是仅凭“开启成功”能保证的性能收益。

所有对照项的最终原始画面 CRC 和 LCD 游戏区域 CRC 一致；CPU 校验值均为 `-1082513742`。全部 `scale_mismatch=0`、`hot_live=0`、PSRAM 差值 0、`JIT_MEMORY live=0`。

音频两组均完整播放 WAV 3.000000 s 和 MIDI 3.139682 s，接收 135,380 源 PCM 帧，输出 297,472 个 48 kHz 立体声帧，codec 错误和欠载均为 0。没有人工听音或麦克风音质评价。

板级接入包含可执行内存回调、`fence.i`、32 KiB 上限和驱动余量检查。SDK 默认内存保护禁用后才能使用可执行堆；申请时避开 SDK 通用的 EXEC/8BIT 组合限制，驱动余量同时计算 SDK 的独立 DMA 预留池。JIT 分发函数与解释器一起放在 IRAM。早期“已安装但代码分配全被拒绝”的两轮日志单独保留，未当作成功结果。

## 游戏测试边界

六款新增游戏各运行 300 个 VM 帧，输入脚本见 [game_scenarios.json](../tests/game_scenarios.json)。`7b12084` 的 240×320 回归全部正常退出，收到各自的 10 个按键边沿，缩放错误 0，内部热数据和 PSRAM 全部回收。俄罗斯方块、钻石狂潮、蹦球传说的短场景实际输出 PCM，三个场景记录到的 codec 错误、音频欠载均为 0；另三款没有在该脚本到达的场景输出 PCM，不能据此断言其声音可用。

在 `fed8d0c` 上开启 JIT 后，六款同样各完成 300 帧和 10 个输入边沿，均有非零原生执行计数，正常退出且缩放、代码缓存、内部热数据和 PSRAM 回收检查通过。钻石狂潮及蹦球传说各记录 1 次音频欠载，Tetris 为 0；相同脚本的前一轮关闭 JIT 测试中这三款均为 0。因此也不把 JIT 视为音频改进。场景动画、计时器和音频位置随运行速度变化，六款并不全部具有相同最终 CRC，不用它们作严格逐像素的 JIT 等价证明。

部分游戏捕获了 Java 异常：俄罗斯方块出现 Vector.firstElement 的 NoSuchElementException；涂鸦地带尝试加载缺失的 `/l/1.png`–`/l/3.png`；首次测试的空存档目录出现 RecordStoreNotFoundException，钻石狂潮还出现 RecordStoreNotOpenException/InvalidRecordIDException。未将这些启动、输入和退出测试视为全部关卡可玩证明。为保留同步能力，没有在子模块中修改游戏兼容性实现。

## 复现

```sh
bash tools/idf.sh build
bash tools/idf.sh -p /dev/ttyUSB0 -b 2000000 app-flash
python tools/benchmark.py build/jit-on.json --jit on
python tools/benchmark.py build/jit-off.json --jit off
python tools/test_games.py build/games-240.json --jit on
python tools/serial_console.py smoke
python tools/test_scaler.py
```

音频重采样逐样本校验覆盖 10 种采样率、3,361,873 个立体声输出帧；显示矩形对照覆盖 1,800 帧，ASan/UBSan 通过。最新上游的 JIT 接口、编码、线程生命周期、M3G、Micro3D、IO、RMS 共 7 项选定主机测试通过；编码矩阵覆盖 8 种 ISA 配置和无效配置拒绝。主机没有执行 RV32 指令，实际原生执行证据来自本板。

最终固件应用 SHA-256：`30ded38e684531144c5de29cd2d7c107e9f56393e8d82aea57fb8fac9fdf780f`。与 JIT 对照固件的功能区别仅为启动时默认关闭 JIT。

源码依据、反汇编和按优先级排列的上游改动建议见 [RV32 JIT 修改建议](JIT_REVIEW.md)。

最终固件的三轮内置演示退出后 PSRAM 均为 **13,708,768 B**，按键和指针到达 Java；FPS 开关、关闭恢复、错误 CRC 清理、截图握手超时恢复均再次通过。FPS 开启的固定重绘为 8.0718 s，两个画面 CRC 保持正确。

240×320 的交互脚本探索截图中，涂鸦地带按数字 6 后人物位置发生变化、教程提示消失；蹦球传说进入实际第一关，显示 0/30 和 0:01 的计时。涂鸦地带的资源布局仍按游戏自身尺寸绘制，240×320 缓冲有空白边。截图见本机 `build/upstream-games/doodle-240-stage.png`、`doodle-240-right.png`、`bounce-240-stage.png`。探索脚本在随后一次高速截图时因串口行长度校验失败中止，已停止游戏返回菜单；因此不宣称整组六款的交互探索脚本通过。该次退出的 `scale_mismatch=0`，所有 VM/代码内存正常回收。截图期间的停顿与欠载不作为性能结论。

最终回到菜单：240×320、音量 40、FPS 关闭、JIT 关闭；FAT 剩余 397,312 B，上传保护余量 262,144 B。测试目录独立于正常 RMS，未清理或覆盖用户存档。
